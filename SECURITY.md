# Политика безопасности

## 🔐 Сообщить об уязвимости

**Не создавай публичный Issue**, если нашёл уязвимость — это может навредить пользователям, пока проблема не исправлена.

### Как правильно

1. Открой **приватный Security Advisory:**
   [github.com/darkjoons3-hue/DarknessTool/security/advisories/new](https://github.com/darkjoons3-hue/DarknessTool/security/advisories/new)
2. Опиши:
   - Что за уязвимость.
   - Как воспроизвести.
   - Возможные последствия.
   - Твоё имя/ник для упоминания в благодарностях (по желанию).

### Что произойдёт

- Я подтвержу получение в течение **3 рабочих дней**.
- Оценю серьёзность и сообщу план исправления.
- После фикса — опубликую релиз с пометкой в CHANGELOG.
- Тебя упомяну в благодарностях (если не против).

## ⚠️ Что считается уязвимостью

- **Утечка данных** — программа отправляет что-то наружу без согласия пользователя.
- **Обход UAC / повышение привилегий** — эксплуатация через DarknessTool.
- **Загрузка произвольного кода** — если скрипты или плагины позволяют выполнить что угодно без подтверждения.
- **Слабости карантина** — если файл может «сбежать» или быть восстановлен не туда.
- **Подмена бэкапов** — если malware может подменить `.reg` в бэкапах.

## 🛡 Что НЕ считается уязвимостью

- **Антивирус ругается** — это ложное срабатывание, не баг безопасности.
- **Требуются права администратора** — это ожидаемое поведение.
- **Программа может удалить важный ключ реестра** — пользователь сам подтверждает действие, это фича.

## 🔒 Принципы безопасности DarknessTool

- **Никакой телеметрии.** Программа не отправляет данные никуда, кроме VirusTotal (только хэши, и только при явном действии пользователя).
- **Все изменения — с бэкапом.** Перед любой операцией создаётся точка отката.
- **Опасные действия — с двойным подтверждением.** Кастомный диалог с явным описанием.
- **Открытый код.** Любой может проверить, что делает программа.
